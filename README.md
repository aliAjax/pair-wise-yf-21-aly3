# hxyfront-62009 地毯修复纹样档案 · 版本账

手工地毯修复工作室的纹样与修复档案前端。核心解决「模板一升级、在修毯子跟着变、配好的线被打回、交接师傅各按一版」的问题：把**地毯档案、工艺模板、工序**接成一本版本账。

页面保留档案所需的产地、年代、结密度、材质、染色类型、破损区域、材料色卡与按产地筛选，并在此基础上增加版本账、工序快照与开工锁。

## 版本账规则

1. **开工钉版**：开工时记下所用模板版本（`pinnedVersionId`），每道工序按该版参数（结密度、染色、色卡、工艺要求）展开为快照；之后模板升级不改钉版。
2. **普通升级（软升级）**：只刷新「未开始」工序的版本与参数；进行中、已完工的工序保留各自当时版本。
3. **色卡 / 结密度改动（硬变更）**：所有未完成工序（**含进行中**）整道作废、留痕（记录作废原因与替代工序编号），按新版重算生成替代工序（`#r1`、`#r2`…）；已完工工序不动，参数永久封存于完工时版本。
4. **历史档案回填**：早先档案按入库时间匹配「当时已生效的最新一版」（入库早于全部版本时取最早版），挂**待确认**；确认前不得开工，确认后开工即沿用该回填版本。
5. **并发开工**：两位师傅同时对同一块毯提交开工，先到者锁定（记录锁定人、时间、钉版），后到者只收到回执，写明锁在谁手里、钉的是哪一版，不产生工单。完工后锁释放。

## 界面

- **档案列表**：按产地筛选，显示修复状态、钉版号、回填待确认标记
- **工单详情**：开工钉版/回填信息、开工受理回执、每道工序的版本号+参数快照、作废留痕折叠区、推进按钮（进行中必须先完工才能开下一道）
- **工艺模板版本**：四个产地模板的版本时间线；可发布新版本（改色卡/结密度自动标记为硬变更并给出传播提示）
- **版本账流水**：开工、拒锁、升级、工序传播、作废重算、回填确认、完工的完整时间线

## 技术栈与运行

React 19 + Vite + TypeScript，纯前端，账本存 localStorage（可「重置演示」回放种子数据）。

```bash
npm install
npm run dev      # http://localhost:62009
npm run build
```

开发端口：62009

## 代码结构

- `src/types.ts`：档案 / 模板版本 / 工单 / 工序快照 / 开工回执数据模型
- `src/engine.ts`：纯函数版本账引擎（开工锁、回填、软/硬升级传播、工序推进），种子数据也通过同一套动作过账
- `src/store.tsx`：React 状态层与持久化
- `src/components/`：档案列表、工单详情、模板版本、版本账流水
